# 第4章　物語構造の解剖 ―― 快楽供給のエンジニアリング

> **本章の要点**
> WEB小説の構造は、従来の物語論とは**最適化の対象が違う**。三幕構成が「全体としての満足」を設計するのに対し、WEB小説は「**各話ごとの離脱阻止**」を設計する。この差は劣化ではなく、連載・無料・離脱自由という条件下での合理である。本章では、その設計原理を、マクロ（作品全体）・メゾ（章・アーク）・ミクロ（1話）の三つの階層で解剖する。

---

## 4-1　従来の物語論との比較 ―― 何が同じで、何が違うか

### 三幕構成・ヒーローズジャーニーとの比較

映画脚本の標準的な設計である三幕構成は、次のような形をとる。

```
第一幕（25%）：日常 → 事件 → 拒否 → 決断
第二幕（50%）：試練の連続 → ミッドポイント → 悪化 → どん底
第三幕（25%）：反撃 → クライマックス → 解決
```

この設計の中核にあるのは、**「主人公が最も苦しむ瞬間（どん底）を全体の75%地点に置く」**という配分である。読者・観客は、その苦痛への投資に対する利子として、クライマックスの解放を受け取る。

WEB小説の連載作品は、この構造をほとんど採用しない。理由は明快である。

> **無料連載で「第二幕の後半（どん底）」に相当する部分を長く書けば、読者は単に読むのをやめる。**

映画の観客は、チケット代を払い、座席に座り、二時間の拘束を受け入れている。文庫本の読者も、代金を払い、手元に物理的な本がある。しかしWEB小説の読者は、いつでも、ノーコストで、指一本で離脱できる。**投資がないので、忍耐もない。**

この非対称性が、WEB小説の構造を決定づけている。

### 起承転結との比較

四段構成の「転」――予想外の展開による方向転換――も、WEB小説では扱いが難しい。読者はタグと長文タイトルによって「何が起きるか」を事前に約束されて来ている。**予想外は、しばしば裏切りとして受け取られる**。

したがってWEB小説の展開は、「転」よりも「**展**」――予告された方向に、予告よりも大きく展開する――に近い。約束は守り、規模で驚かせる。

### では、何と似ているのか

WEB小説の構造にもっとも近いのは、**連続テレビドラマ、週刊連載マンガ、そしてソーシャルゲーム**である。

| 形式 | 共通する条件 |
|---|---|
| 週刊マンガ | 各話に山場が必要。次号を待たせる引きが必要。打ち切りリスク |
| 連続ドラマ | 視聴率＝各話の離脱率。継続視聴の動機づけ |
| ソーシャルゲーム | 短いセッション、継続報酬、成長の可視化、飽きへの対策 |

とくにソーシャルゲームとの構造的類似は示唆的である。**レベル、スキル、収集、拠点の成長、定期的な報酬**――これらはゲームデザインの語彙であり、WEB小説はそれを物語に移植している。

## 4-2　離脱率の物語論

### 基本モデル

WEB小説の読者行動を、次のように単純化してモデル化してみよう。

```
各話の終了時点で、読者は「続きを読む」か「やめる」かを選ぶ。
継続率が r（0 < r < 1）のとき、n話目まで残る読者は初期読者の r^n。
```

r = 0.95 なら、50話後に残るのは 8%。r = 0.98 なら 36%。**わずか3ポイントの差が、4倍以上の読者数の差になる**。

この単純なモデルから、二つの重要な帰結が出る。

**帰結①：初期の脱落がすべてを決める。**
実際の継続率は均一ではなく、序盤で極端に低い。第1話 → 第2話の継続率はしばしば50%を下回る。つまり、**冒頭で失う読者が全体の大半**である。だから冒頭設計に全力が注がれる。

**帰結②：一度の大きな不快は、百回の小さな快楽を打ち消す。**
継続率は「良い話があったか」ではなく「**やめる理由があったか**」で決まる。行動経済学の損失回避と同じで、**負の刺激は正の刺激より重い**。ここから「ストレス管理」という編集原理が導かれる（→4-8）。

### 「読む理由」から「やめない理由」へ

まとめると、次の視点の転換がWEB小説設計の核心である。

| 従来の問い | WEB小説の問い |
|---|---|
| どうすれば読者を引き込めるか | どこで読者は離脱するか |
| クライマックスをどう盛り上げるか | 谷間をどう浅くするか |
| 主人公をどう苦しめるか | 苦しみをどこまで許容できるか |
| 何を書くか | 何を書かないか |

## 4-3　冒頭の設計 ―― 第1話、3話、10話の三つの関門

### 関門1：タイトルとあらすじ（クリック前）

読者が最初に接触するのは本文ではない。**タイトルとあらすじの冒頭一行**である。ここで作品が何であるかが伝わらなければ、本文は読まれない（詳細は第8章）。

### 関門2：第1話（クリック後、最初の1分）

第1話が果たすべき機能は五つある。

| 機能 | 内容 | 目安 |
|---|---|---|
| ①約束の提示 | タイトルが約束したものを本文でも即座に確認させる | 冒頭300字以内 |
| ②主人公の設置 | 誰の視点で読むのかを確定させる | 冒頭200字以内 |
| ③状況の設置 | どんな世界の、どんな場面か | 冒頭500字以内 |
| ④フックの提示 | この作品だけの引っかかり（能力、境遇、謎） | 1話の中盤 |
| ⑤引き | 次を読ませる未解決 | 1話の末尾 |

**よくある失敗**：世界観の説明から始める。主人公の日常を丁寧に描く。伏線を張ることに集中する。これらはすべて、紙の本では美徳だが、WEB連載の第1話では致命的になりうる。

**定石**：「①約束の提示」を最優先する。追放ものなら第1話で追放される。悪役令嬢ものなら第1話で自分が悪役令嬢だと気づく。転生ものなら第1話で転生する。**読者が求めて来たものを、待たせずに出す**。

### 関門3：第3話（「3話の壁」）

多くの読者は、3話まで読んで継続を判断すると言われる。この段階で必要なのは、

- **快楽エンジンの初回作動**：この作品を読み続けると、どんな気持ちよさが得られるかの実演
- **反復可能性の提示**：それが一回きりでなく、繰り返し供給されるという予感

追放ものであれば、3話目までに「追放された主人公の価値が、外部の誰かに認められる」場面を置く。無双ものなら、3話目までに一度は圧倒的な力を見せる。**「この先も同じ快感が来る」と読者に信じさせること**が、3話までの仕事である。

### 関門4：第10話前後（「10話の壁」）

初期の勢いが尽き、日常が始まる地点。ここで必要なのは、

- **中期目標の設定**：短期の目的（生き延びる、街に着く）が終わったあと、次に何を目指すのか
- **関係の定着**：継続的に登場する仲間・拠点・所属
- **世界の拡張の予告**：まだ見ていない場所・敵・秘密の存在

多くの作品が10〜20話の区間で失速する。原因のほとんどは、**目的の空白**である。

## 4-4　快楽供給のスケジューリング ―― カタルシス・エンジン

### 「エンジン」という考え方

WEB小説を分析するときに有効なのが、**「この作品は何をエンジンにして走っているか」**という問いである。エンジンとは、**繰り返し作動して、そのたびに読者に報酬を与える構造**を指す。

たとえば――

| エンジン | 作動の形 | 燃料（消耗するもの） |
|---|---|---|
| 無双 | 強敵が現れ、圧倒する | 「まだ見ぬ強敵」の在庫 |
| ざまぁ | 侮った者が真価を知る | 「侮る者」の在庫 |
| 勘違い | 認識のズレが好結果を生む | ズレを維持する状況の在庫 |
| 収集 | 新しいスキル・仲間・拠点を得る | 未取得のものの在庫 |
| 承認 | 周囲が主人公を再評価する | 未評価の観測者の在庫 |
| 謎 | 疑問が生じ、解かれる | 未解決の謎の在庫 |

**重要な洞察は、すべてのエンジンには燃料があり、燃料は有限である**ということだ。

「侮る者」を出し続ければ、世界の住人が全員バカに見えてくる。「まだ見ぬ強敵」を出し続ければ、インフレが起きる。「新しいスキル」を出し続ければ、能力体系が破綻する。

したがって長期連載の設計とは、**エンジンの燃料補給計画**である。

### 燃料の補給方法

| 方法 | 説明 | 例 |
|---|---|---|
| 舞台の移動 | 新しい土地には、主人公を知らない人がいる | 王都へ、隣国へ、迷宮の下層へ |
| スケールの上昇 | 相手の格を上げる（個人→組織→国家→世界） | ギルド員→貴族→王→神 |
| エンジンの交代 | 途中で別のエンジンに乗り換える | 無双→内政、ざまぁ→スローライフ |
| エンジンの複線化 | 二つ以上を並行させ、交互に作動させる | 戦闘パートと生産パート |
| 視点の追加 | 別のキャラの視点で同じ出来事を再体験 | 敵側視点、仲間視点 |

> **実務上の指針**：連載を始める前に、**「このエンジンの燃料は何話分あるか」**を見積もっておく。50話で尽きるエンジンで200話を書こうとすると、必ず中盤で失速する。

### 報酬のリズム

具体的な配分の目安として、多くの成功作に見られるパターンを挙げる（絶対的な規則ではなく観察）。

```
毎話　　　：小さな快（新情報、軽い称賛、テンポの良い会話、引き）
3〜5話ごと：中程度の快（戦闘の勝利、問題の解決、新しい仲間）
15〜30話ごと：大きな快（アークの完結、正体の露見、大規模なざまぁ）
```

そして**負の刺激（ストレス）は、必ず直後に解消の目処を提示する**。「主人公が窮地に陥る → 次話で解決」という短いスパンが基本で、「窮地が30話続く」構成はWEB連載ではきわめて危険である。

## 4-5　「ざまぁ」構造の解剖

WEB小説を象徴する構造として、「ざまぁ」を詳細に分解しておく。これは単なる復讐譚ではなく、**精密に設計された感情の機械**である。

### 五段階モデル

```
【第1段階】設置（Injustice）
　主人公が不当に低く評価される。可能なら公衆の面前で。
　→ 読者に「怒り」を装填する。この怒りが以後の推進力になる。

【第2段階】離脱（Separation）
　主人公が加害者の側から物理的に離れる（追放、出奔、パーティ解散）。
　→ 二つの運命が分岐し、比較可能になる。

【第3段階】二重進行（Divergence）
　主人公は外部で正当に評価され、上昇する。
　加害者側は主人公の不在によって凋落する。
　→ この対比の描写こそが、ざまぁの本体である。

【第4段階】露見（Revelation）
　加害者が「自分が何を失ったか」を理解する。
　→ 最大のカタルシス。読者が待っていた瞬間。

【第5段階】拒絶（Refusal）
　加害者が謝罪・復帰要請に来るが、主人公は関心を示さない。
　→ 主人公の格の証明。復讐ではなく「もう眼中にない」という形が好まれる。
```

### 設計上の要点

**要点1：怒りの装填は精密に。**
第1段階の不当さが弱ければ、読者は怒らない。強すぎれば不快になって離脱する。定番は「**不当だが、一応の言い分はある**」という水準である（例：「戦闘力が低い」「地味な支援職だ」という表面的には筋の通った理由）。

**要点2：主人公は復讐しない。**
成功している作品のほとんどで、主人公は加害者を積極的に攻撃しない。**加害者は自滅する**。理由は二つ。①主人公が攻撃すると、読者の道徳的同一化が崩れる。②「相手にする価値もない」という態度のほうが、格の証明として強い。

**要点3：第三者の評価を挟む。**
主人公の価値を主人公自身が主張すると、傲慢に見える。**別のキャラクターが驚き、称賛する**構造にすると、同じ内容が「正当な評価」として読める。これがWEB小説で視点切り替え（他者視点の挿入話）が多用される最大の理由である。

**要点4：拒絶の温度。**
第5段階で主人公がどう振る舞うかで作品の性格が決まる。

| 温度 | 主人公の反応 | 読後感 |
|---|---|---|
| 冷 | 「あなた、誰でしたっけ」 | 痛快、爽快 |
| 中 | 「もう関わらないでください」 | すっきり |
| 温 | 「あなたも幸せに」 | 品格、余韻 |
| 熱 | 積極的に破滅させる | 濃厚だが読者を選ぶ |

### 女性向けにおける変奏

婚約破棄ものは、この五段階を**第1話に第1段階と第2段階をまとめて置く**という圧縮を行う。「公衆の面前での婚約破棄」という一場面で、不当な評価と離脱が同時に達成されるためである。この圧縮効率の高さが、婚約破棄という設定が繰り返し使われる構造的理由である。

## 4-6　1話の内部構造（ミクロ）

### 標準的な1話の設計

```
[冒頭 100〜300字]  前話からの接続／状況の確認
[展開 1,000〜2,000字]  この話の主題となる出来事
[山　 500〜1,000字]  この話の最大の見せ場（快の供給点）
[引き 100〜300字]  次話への未解決
──────────────────
合計 2,000〜4,000字
```

### 「1話1イベント」の原則

WEB小説の1話には、**原則としてひとつの出来事しか入れない**。理由は、

- 読者が細切れに読むため、複数の出来事が混ざると記憶が保たない
- 1話ごとに感想・評価が入るため、話の焦点が明確なほど反応を得やすい
- コミカライズ時に1話単位が変換しやすい

### 引きの類型

| 型 | 例 | 効果 |
|---|---|---|
| 事件発生型 | 「その時、鐘が鳴り響いた」 | 最も強いが、多用すると疲れる |
| 情報開示型 | 「その男の名は――」 | 次話の内容を予告する |
| 感情型 | 「私は、彼を許せなかった」 | 心理の続きを読ませる |
| 予告型 | 「翌日、私は王城に呼ばれることになる」 | 穏やかだが確実 |
| 反応待機型 | 主人公がすごいことをして、周囲が絶句した所で終わる | 称賛の受領を次話に持ち越す |

**注意**：毎話を「事件発生型」で終わらせると、読者の緊張が持続せず、逆に麻痺する。**穏やかな引きと強い引きを交互に**配置するのが実務的である。

## 4-7　マクロ構造 ―― 章とアークの設計

### 「章（アーク）」という単位

長期連載は、10〜40話程度の「章」の連なりとして構成される。ひとつの章は、それ自体が小さな三幕構成をなす。

```
章の導入（2〜4話）：新しい舞台・課題・人物の提示
章の展開（5〜25話）：課題への取り組み、障害、成長
章の頂点（2〜4話）：課題の解決、最大の見せ場
章の余韻（1〜3話）：報酬の受領、関係の定着、次章への布石
```

### 目的の更新（ラダー構造）

長期連載を失速させない最大の技術は、**目的をはしご状に更新すること**である。

```
生き延びる（1〜10話）
　↓ 達成
街で居場所を得る（11〜30話）
　↓ 達成
仲間と拠点を持つ（31〜60話）
　↓ 達成
領地を治める（61〜120話）
　↓ 達成
国を守る（121〜200話）
　↓
世界の秘密に触れる（201話〜）
```

重要なのは、**次の目的が現れるのは、前の目的が達成された「後」ではなく「少し前」**だという点である。達成の直前に次の課題を提示すると、読者は谷間を感じずに次のアークへ移行できる。

### 「完結」の設計

WEB小説の宿命的な問題として、**エタる（未完のまま更新が止まる）**現象がある。理由は複合的だが、構造的には次の三つが大きい。

1. **終点を決めずに始める**――どこまで書けば終わりかがわからないので、終われない
2. **エンジンの燃料切れ**――書く動機が尽きる
3. **拡大しすぎた風呂敷**――伏線と登場人物が増えすぎて畳めなくなる

対策としては、

- **執筆前に最終話の一行を決めておく**（内容ではなく、到達すべき状態）
- **「区切りのよい終わり方」を複数用意しておく**（第1部完、という形で降りられる場所を作る）
- **登場人物の総数に上限を設ける**
- **回収予定のない伏線を張らない**――WEB連載では、伏線は「作者への負債」である

## 4-8　ストレス管理という編集原理

### 「不快」の分類

読者が離脱する原因となる「不快」には、いくつか異なる種類がある。すべてを排除する必要はなく、**種類ごとに扱いを変える**のが正しい。

| 種類 | 例 | 扱い |
|---|---|---|
| 期待の裏切り | 追放ものと言いながら追放されない | **絶対に避ける** |
| 主人公の理不尽な敗北 | 実力が理由なく通じない | 避ける。負けるなら理由を明示 |
| 主人公の無能 | 判断ミス、鈍感さによる失敗 | 慎重に。読者は主人公と同一化している |
| 大切なものの喪失 | 仲間の死 | 強力だが劇薬。回復の目処とセットで |
| 加害者の勝利 | 悪役が得をし続ける | 短期なら可。長期は危険 |
| 生理的嫌悪 | 過度な暴力、性的加害 | タグで警告し、必要性がなければ削る |
| 退屈 | 何も起きない | **最も見過ごされがちな不快** |

### 「ストレスフリー」タグの意味

近年、「ストレスフリー」「胸糞展開なし」といったタグが機能している。これは読者が**あらかじめ不快の有無を確認して読み始める**ことを意味する。

これを「読者の耐性の低下」と嘆くこともできるが、より正確には、**選択肢が無限にある環境における合理的な選別行動**である。読者は不快に耐える理由がない。作者にできるのは、①不快を入れないか、②入れるなら事前に告知して、それでも読みたい読者だけを相手にするか、である。**中途半端に告知せず入れるのが最悪**である。

## 4-9　伏線と回収 ―― WEB連載における特殊事情

紙の本と異なり、WEB連載の読者は**前を読み返さない**。この事実は、伏線の扱いを根本的に変える。

**（1）伏線は「読者が覚えている」ことを前提にできない。**
回収時には、伏線の内容を短く再提示する必要がある。「あのとき彼が言った『鍵』という言葉――」のように。

**（2）長すぎる伏線は機能しない。**
100話前の一行を回収しても、ほとんどの読者は気づかない。**実効的な伏線の射程は、せいぜい20〜30話**である。

**（3）代わりに「予告」が効く。**
伏線（気づかれずに置かれ、後で意味が判明する）よりも、**予告**（明示的に「これは後で重要になる」と示す）のほうが、WEB連載では有効である。読者は「回収されるはず」と期待して待ち、回収時に満足する。

**（4）感想欄が伏線の管理装置になる。**
読者が考察を書き込むため、伏線は集合的に記憶される。ただしこれは諸刃で、**予想が当たると驚きが失われ、外すと落胆される**。
