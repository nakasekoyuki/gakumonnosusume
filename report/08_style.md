# 第8章　文体・技法・タイトル ―― 読まれるための工学

> **本章の要点**
> WEB小説の文体は「下手な文章」ではなく、**特定の読書環境に最適化された組版と語りの体系**である。一人称の優位、高い会話比率、多い改行、説明的な長文タイトル――これらはすべて、スマートフォンの画面、細切れの読書時間、無料での試し読み、ランキング一覧という条件から導かれる。本章では、その工学を具体的な作法として記述する。

---

## 8-1　人称と視点 ―― なぜ一人称が支配的なのか

### 一人称の四つの利点

WEB小説では一人称（「俺は」「私は」）が圧倒的に優勢である。理由は次の四点に整理できる。

**（1）読者の同一化が速い。**
三人称では読者は主人公を「見る」が、一人称では「なる」。離脱率との戦いにおいて、この0.5秒の差は大きい。

**（2）異世界への驚きを共有できる。**
現代から来た主人公の内面独白は、そのまま**読者の代弁**になる。「ステータス？ ゲームかよ」「マジで異世界か」――この驚きの共有が、世界説明を兼ねる。三人称で同じことをすると、説明臭くなる。

**（3）ツッコミが書ける。**
テンプレ的な状況に対して主人公が内心でツッコミを入れる、という技法は一人称でしか成立しない。これはコメディの供給源であると同時に、**作者と読者が「この設定がお約束であること」を共有する合図**でもある。

**（4）書きやすい。**
実務的な理由だが無視できない。視点の統一が容易で、書き手の負荷が低い。毎日更新には重要な条件である。

### 一人称の弱点と、その補償

一方、一人称には決定的な弱点がある。**主人公が知らないことを書けない**。

- 主人公のすごさに周囲がどう驚いているか、内心までは書けない
- 敵側の事情、遠隔地の出来事が書けない
- 主人公が鈍感な場合、ヒロインの好意が読者にも伝わらない

この弱点を補うために、WEB小説は**視点切り替え**を大胆に使う。

| 技法 | 内容 | 効果 |
|---|---|---|
| **他者視点の挿話** | 章の合間に「◇◇視点」の話を挟む | 主人公のすごさを外から見せる。**承認エンジンの燃料補給** |
| **幕間（インターミッション）** | 敵側・仲間側の動きを描く独立話 | 世界の広がりと緊張の提示 |
| **一話内での切り替え** | 罫線や「Side:◯◯」で区切る | 手軽だが、多用すると散漫になる |
| **三人称への部分的移行** | 大規模な戦闘・会議シーン | 情報量が必要な場面に有効 |

**実務的な指針**：他者視点の挿話は、**勘違い系・無双系では必須の装置**である。主人公が自分の異常さに無自覚であればあるほど、外部視点の価値が上がる。ただし挿入頻度が高すぎると、主人公への同一化が薄れる。目安としては**5〜10話に1回程度**。

### 三人称を選ぶ場合

三人称が有効なのは、

- 群像劇（複数の主人公級キャラが並立する）
- 叙事詩的なスケール（国家、戦争、歴史）
- 主人公が徹底して謎めいた存在である場合
- 主人公が非常に若い／非人間で、内面の言語化が不自然な場合

ただしWEB連載では**初速で不利になる**傾向がある。三人称で書くなら、その分、冒頭の掴みを強化する必要がある。

## 8-2　文章の物理設計 ―― 画面上の見た目

### 段落と改行

紙の小説の標準的な段落は5〜15行だが、WEB小説では**1〜3行**が標準である。

```
【紙の作法】
　彼は森の奥へと歩みを進めた。木々の間から差し込む陽光は
斑に地面を照らし、湿った土の匂いが鼻を突く。遠くで鳥が鳴
いた。その声は妙に鋭く、まるで警告のようにも聞こえた。彼
は足を止め、腰の剣に手をかける。何かがいる。確信ではなく、
長年の経験が告げる直感だった。

【WEB小説の作法】
　森の奥へ進む。

　木々の隙間から陽が差し込んでいた。湿った土の匂い。

　遠くで鳥が鳴いた。妙に鋭い声だ。

　……警告？

　足を止め、剣に手をかける。
　何かいる。確信じゃない。ただの勘だ。
```

後者は情報量が少ないわけではない。**同じ情報を、視覚的に分割して提示している**。スクロールの快感、視線の移動の速さ、一息で読める単位――これらを優先した組版である。

### 会話比率

WEB小説では、会話が全体の40〜60%を占めることが珍しくない。会話が多いことの効果は、

- 空白が増え、画面が軽く見える
- 読む速度が上がる
- キャラクターの個性が出やすい
- 情報を「教える」のではなく「やりとりする」形にできる

**注意点**：会話だけで情報を伝えようとすると、キャラクターが読者への説明役になり、不自然になる（「そうだ、知っての通りこの国は……」）。**会話が地の文の代用になってはいけない**。

### 記号と表記

WEB小説では、紙の小説では避けられる記号表現が多用される。

| 表現 | 用途 | 注意 |
|---|---|---|
| 「……」 | 沈黙、ためらい | 多用すると弛緩する |
| 「――」 | 断絶、転換、強調 | 効果的だが乱発しない |
| 【スキル：鑑定】 | ゲーム的UI表現 | 視覚的に強い。頻度を制御する |
| 傍点・太字 | 強調 | サイトによって表示が異なる |
| ！？ | 驚き | 会話の温度を上げる |
| 心内語の（　） | 内心の別声 | 一人称では不要なことが多い |
| ルビ | 二重の意味づけ | 「世界最強《オーバーロード》」型。中二病的な効果 |

### 一話の分量

| 分量 | 特徴 |
|---|---|
| 1,000字未満 | 更新頻度は上がるが、読み応え不足。PV型サイト向き |
| 2,000〜3,000字 | **最も標準的**。1セッションで読み切れる |
| 3,000〜5,000字 | 読み応えがあるが、毎日更新は負担 |
| 5,000字以上 | 離脱リスクが上がる。分割を検討 |

## 8-3　テンポの技術

### 情報密度の制御

WEB小説の「テンポが良い」とは、具体的には**一文あたりの新情報が多く、かつ読解の負荷が低い**状態を指す。

**テンポを落とす要因**
- 長い修飾（「彼は、かつて王都で名を馳せた剣士であった父から受け継いだ、銀の装飾が施された古い剣を」）
- 主語の遠さ（主語と述語のあいだが長い）
- 抽象語の連続（「彼の心には複雑な感情が去来していた」）
- 説明のための説明（設定の解説が物語を止める）
- 同じ情報の反復（意図的な反復は有効だが、無自覚なそれは冗長）

**テンポを上げる技術**
- 一文を短く切る
- 具体名詞を使う（「感情」ではなく「怒り」、「装備」ではなく「鉄の剣」）
- 動詞で進める（状態描写より動作）
- 体言止めの適度な使用
- 会話で局面を転換する

### 「読み飛ばされる文」を減らす

WEB小説の読者は、しばしば斜め読みする。読み飛ばされやすいのは、

1. 長い風景描写
2. ステータス表示の繰り返し
3. 戦闘の技術的な詳細
4. 過去の説明・回想

これらを完全に排除する必要はないが、**読み飛ばされても物語が追える構造**にしておくのが実務的である。すなわち、**重要な情報は会話か短い地の文に置く**。

## 8-4　タイトルの工学

### なぜタイトルは長いのか

ランキング一覧・新着一覧で読者が見るのは、**タイトルと、あらすじの冒頭数十字だけ**である。表紙も、帯も、書店員の推薦もない。

したがってタイトルは、次のすべてを担う。

| 通常の書籍における担い手 | WEB小説では |
|---|---|
| 表紙イラスト | タイトル |
| 帯のキャッチコピー | タイトル |
| ジャンル表示 | タイトル |
| あらすじ | タイトル |
| レーベルの信頼 | タイトル |

情報を詰め込む圧力は、構造的なものである。「タイトルが長いのは幼稚だから」ではなく、**唯一の広告枠だから**である。

### 長文タイトルの構文分類

実際のタイトルは、いくつかの定型的な構文に分類できる。

**① 状況＋逆転型**
> 「〈無能〉と追放された俺、実は世界最強でした」
>
> 構造：[不当な評価]＋[実際の価値]。ざまぁの約束を一行で行う。

**② 因果連鎖型**
> 「〜と言われたので、〜することにした」
>
> 構造：[きっかけ]＋[主人公の選択]。主人公の能動性と方針を示す。

**③ 状態宣言型**
> 「転生したら〇〇だった件」
>
> 構造：[経路]＋[結果]。もっとも簡潔で、汎用性が高い。

**④ 目的提示型**
> 「〜するために〜します」
>
> 構造：主人公の欲望を明示する。長期連載の方向性を示せる。

**⑤ 逆説・ギャップ型**
> 「最強の〇〇ですが、〜したいだけなんです」
>
> 構造：[能力]と[願望]のずれ。スローライフ系の定番。

**⑥ 会話・独白型**
> 「〜って言われても困るんですが？」
>
> 構造：主人公の声で始める。人称と性格が即座に伝わる。

**⑦ 列挙型**
> 「〇〇で、〇〇で、〇〇な私が〇〇する話」
>
> 構造：要素を並べる。情報量は多いが、長すぎると読まれない。

### タイトル設計の実務

**（1）最初の15字が勝負。**
一覧表示では末尾が省略されることがある。**冒頭に最重要の要素を置く**。

**（2）四つの情報のうち、三つを入れる。**
- **世界**（異世界／転生／ダンジョン）
- **立場**（追放された／悪役令嬢／最強）
- **行動**（〜します／〜する話）
- **感情**（ざまぁ／溺愛／のんびり）

すべてを入れると長すぎ、二つでは足りない。**三つが実用的な最適点**である。

**（3）約束したことは必ず果たす。**
タイトルは読者との契約書である。「最強」と書いたのに弱ければ、「スローライフ」と書いたのに戦い続ければ、低評価が入る。

**（4）差別化の一語を入れる。**
テンプレ構文のなかに、**一つだけ他と違う語**を混ぜる。「追放された聖女」は無数にあるが、「追放された聖女、辺境で図書館を開く」なら記憶に残る。

**（5）短いタイトルは、それ自体が差別化になりうる。**
すべてが長文である環境では、簡潔なタイトルが逆に目立つ。ただし、**中身を説明するあらすじが優秀であることが条件**になる。

## 8-5　あらすじの設計

タイトルの次に読まれるのが、あらすじ（作品紹介文）である。ここで果たすべき仕事は、

```
①冒頭1〜2行で、タイトルの約束を具体化する
②主人公の状況と目的を示す
③この作品固有の「引っかかり」を提示する
④読者が得られる体験（快楽エンジン）を予告する
```

**構成テンプレート（実用形）**

```
［1〜2行］状況の提示。「〜だった。しかし〜」
［3〜5行］転機と、主人公の選択
［1〜2行］この先どうなるか、または主人公の宣言
［1行］補足（更新頻度、完結予定、注意事項など）
```

**よくある失敗**
- 世界設定の説明から始める（読者は世界に興味がない。**主人公に興味がある**）
- 抽象的な惹句だけで、内容がわからない
- 長すぎる（一覧表示では冒頭しか見えない）
- 「初投稿です」「拙い文章ですが」といった予防線（読者に読まない理由を与える）

## 8-6　タグ（キーワード）戦略

### タグの三つの機能

1. **検索されるため**――読者が「ざまぁ」「スローライフ」で絞り込む
2. **期待を調整するため**――「ざまぁ」「ハッピーエンド」「主人公最強」
3. **警告のため**――「残酷な描写あり」「鬱展開」「主人公総受け」

### 実務上の原則

- **中身と一致させる**。過大なタグ付けは低評価を招く
- **警告タグは必ず付ける**。付け忘れが最大の炎上要因
- **少なすぎない**。10〜20程度が標準
- **多すぎない**。関係の薄いタグを大量に付けるのは規約違反の可能性があり、読者の信頼も損なう
- **人気タグと固有タグを混ぜる**。人気タグで発見され、固有タグで記憶される

## 8-7　更新戦略と読者コミュニケーション

### 更新頻度

第1章で見たとおり、日間ランキングは**ポイントの増分**を測る。したがって更新は露出に直結する。

| 戦略 | 内容 | 適する状況 |
|---|---|---|
| **毎日更新** | 最も効果的。習慣化を促す | 連載開始直後、ランキング狙い |
| **一日複数更新** | 短期的な集中露出 | 開始直後のブースト |
| **定曜日更新** | 読者が予定を立てられる | 中長期の安定運用 |
| **ストック放出** | 書き溜めてから一気に開始 | 序盤の失速を防ぐ |
| **不定期** | 最も不利 | 完結後、または固定読者がいる場合 |

**実務的な推奨**：連載開始前に**20〜30話をストックし、序盤は毎日または一日2回更新**。これが初速を作るための、もっとも一般的な戦略である。

### 感想欄・レビューとの付き合い方

WEB小説には、読者が直接コメントを書き込む場がある。これは資産であり、同時に負債でもある。

**資産としての側面**
- 誤字脱字の指摘（実際に多くの作者が助けられている）
- 反応の可視化による執筆動機
- 読者の期待の把握（どこで面白がっているか）
- 考察による作品世界の拡張

**負債としての側面**
- 否定的なコメントによる執筆意欲の喪失（**エタりの主要因の一つ**）
- 読者の要望に引きずられ、作品が迷走する
- 特定の読者との議論が長期化する

**推奨される態度**
1. **感想は「読まれている証拠」として受け取る**。内容より存在に意味がある
2. **指摘は取捨選択する**。すべてに応えると作品が壊れる
3. **論争しない**。反論したい気持ちは正当だが、公開の場での応酬は消耗しかない
4. **設定の指摘は、次作以降に活かす**。既に公開した部分の大改稿は、読者を混乱させる
5. **メンタルを守る仕組みを作る**（感想を見る日を決める、通知を切る等）

### 活動報告・作者コメント

多くのサイトには、作者が読者に直接語りかける機能がある。適度な使用は読者との関係を作るが、

- 更新の言い訳が続くと、読者は期待を下げる
- 政治的・社会的な発言はリスクを伴う（→第10章）
- 本編に関係のない長文は、読者の関心を削ぐ

## 8-8　「なろう文体」批判をどう受け止めるか

WEB小説の文体は、しばしば批判される。「稚拙」「説明的」「同じ表現の反復」「語彙が乏しい」等。

これらの批判には、**当たっている部分と、的外れな部分**がある。

### 的外れな部分

- **短い段落・多い改行は「下手」ではない**。メディアへの適応である。同じ文章を紙の書籍に組めば読みにくいが、それは組版の問題であって文章の問題ではない
- **説明的であることは、戻り読みができない環境への適応**である
- **一人称の口語体は、意図された選択**でありうる

### 当たっている部分

- **語彙の貧しさは、実際に多くの作品の弱点**である。「〜だった」「すごい」「思った」の反復は、テンポの問題ではなく単に単調である
- **無自覚な反復**（同じ言い回しが一段落に三度出る）は、単純な推敲不足
- **描写の欠如**。テンポを優先するあまり、読者が何も見えていない状態が続く作品は多い
- **感情の説明**。「悲しかった」と書くだけで、悲しみが伝わらない

### 実務的な結論

> WEB小説の環境は「読みやすさ」を強く要求するが、**「読みやすさ」と「文章が下手であること」は別物**である。
>
> 短い文で、具体的な名詞と動詞を使い、無駄な修飾を削る――これは、ヘミングウェイ以来の散文の王道でもある。WEB小説の作法を守りながら、なお優れた文章を書くことは十分に可能であり、実際にそれを実現している作品が、長期にわたって支持されている。

**推敲の実務チェック**
- [ ] 同じ語尾が3回続いていないか
- [ ] 一段落に同じ単語が3回出ていないか
- [ ] 「思った」「感じた」で済ませている感情はないか
- [ ] 抽象語（気持ち、感情、雰囲気、状況）を具体に置き換えられないか
- [ ] 読者が「何も見えていない」ページがないか（最低限の視覚情報）
- [ ] 声に出して読んで、詰まる場所はないか

## 8-9　本章のまとめ

1. **一人称が標準**。弱点は他者視点の挿話で補う（5〜10話に1回）
2. **段落は1〜3行、1話2,000〜3,000字、会話比率は高め**
3. **タイトルは唯一の広告枠**。冒頭15字に最重要要素、四情報のうち三つ、差別化の一語
4. **あらすじは主人公から書く**。設定からは書かない
5. **タグは契約**。約束と警告を正確に
6. **序盤はストックを持って毎日更新**
7. **感想は資産であり負債**。取捨選択と自衛
8. **読みやすさと文章力は両立する**。推敲は裏切らない
